# Неочевидные моменты для андроидщика

То, что в Android работает "само" или работает иначе, и на чём спотыкаешься в первые месяцы

## Swift

- **`Array`, `Dictionary`, `String` — value types.** Передал массив в функцию или присвоил в другую переменную — это копия (ленивая, copy-on-write). Изменение копии не меняет оригинал. Привычка из Kotlin "у меня есть ссылка на список" здесь ломается
- **struct в `let` неизменяем целиком**, даже его `var`-поля. Методы, меняющие struct, помечаются `mutating`
- **Классы не `final` по умолчанию** (в Kotlin наоборот). Ставить `final class` — хорошая практика и чуть быстрее dispatch
- **Методы из protocol extension не переопределяются полиморфно**, если их нет в самом протоколе. Вызов через тип протокола возьмёт реализацию из extension, а не из класса — классический вопрос на собесе
- **`String` нельзя индексировать `Int`**: `str[0]` не скомпилируется, нужен `String.Index` (из-за Unicode графем). `str.count` — O(n)
- **Краши вместо исключений**: `!` на `nil`, выход за пределы массива, переполнение `Int`, `as!` — краш, `try/catch` не поможет
- **`==` и `===`**: `==` — Equatable, `===` — та же ссылка (только для классов)
- **Argument labels** — часть имени функции: `move(from:to:)`. Привыкнуть к тому, что `_` убирает label
- **`guard`** — идиома ранних выходов, встречается везде, внутри обязателен `return`/`throw`/`break`
- **Extensions не могут хранить свойства** (только computed)
- **`internal` — уровень по умолчанию** (виден во всём модуле), `private` в Swift виден ещё и в extensions того же файла
- **`Codable` и опциональность**: если поле может отсутствовать в JSON, оно должно быть Optional, иначе decoding упадёт целиком
- **Swift 6 strict concurrency** даёт кучу ошибок компиляции про `Sendable` и изоляцию акторов. В новых проектах Xcode по умолчанию весь код изолирован на `@MainActor` — это нормально, фон выносится явно

## Память (ARC)

- **Любая strong-ссылка "туда и обратно" — утечка навсегда.** GC не придёт
- **Closures захватывают `self` сильно.** Если closure хранится в свойстве объекта (или у объекта, которым он владеет) — нужен `[weak self]`. В `UIView.animate` и одноразовых `DispatchQueue.main.async` можно и без weak — closure не хранится
- **`delegate` всегда `weak var`**, и протокол делегата должен быть `AnyObject`, иначе `weak` не поставить
- **`Timer` держит target сильно**, `NotificationCenter` с closure-API — тоже держит closure, надо удалять observer или хранить токен
- **`unowned`** — как `weak`, но без Optional и с крашем, если объект уже умер. По умолчанию лучше `weak`
- **`Task {}` в ViewController захватывает `self`** и держит его, пока задача не закончится
- **Проверка утечек на практике**: `deinit { print("deinit \(Self.self)") }` в экранах/ViewModel, открыть-закрыть экран

## Многопоточность

- **`Task {}` — не `launch` в скоупе.** Нет structured concurrency для неструктурированных `Task`: задача не отменится сама при закрытии экрана (в отличие от `viewModelScope`). Надо хранить `Task` и вызывать `cancel()`, или использовать `.task {}` в SwiftUI — он отменяется сам при исчезновении view
- **`Task {}` наследует актор**: созданный из `@MainActor` кода — выполняется на main actor. Для фона — `Task.detached` или `nonisolated` функция
- **Отмена кооперативная** (как в корутинах): надо проверять `Task.isCancelled` / `try Task.checkCancellation()`
- **Actor reentrancy**: после `await` внутри actor состояние могло измениться — инварианты между await не гарантируются
- **`DispatchQueue.main.sync` с главного потока — deadlock**
- **UI только с main thread**: в UIKit нарушение = странные баги или краш, Main Thread Checker в Xcode ловит это в debug
- **`Timer` во время скролла не тикает**, если добавлен в `.default` mode RunLoop — нужен `.common`

## UI

- **Экран не пересоздаётся при повороте.** Не надо сохранять стейт "на всякий случай" — но надо обрабатывать изменение размеров (`viewWillTransition`, trait collection)
- **`viewDidLoad` — один раз, `viewWillAppear` — каждый раз при показе**, в том числе при возврате назад по стеку. Логику "обновить при возвращении" — туда
- **`frame` vs `bounds`**: frame в координатах родителя, bounds — в своих
- **Размеры в `viewDidLoad` ещё неправильные** — актуальны в `viewDidLayoutSubviews` / `layoutSubviews`
- **`translatesAutoresizingMaskIntoConstraints = false`** — забыл при вёрстке кодом, констрейнты ломаются
- **Ячейки переиспользуются**: в `prepareForReuse` сбрасывать состояние, иначе картинки "прыгают" между ячейками (как в RecyclerView)
- **Клавиатура не сдвигает контент сама** (в UIKit). Нет `adjustResize` — надо `keyboardLayoutGuide` или руками
- **Свайп назад ломается**, если спрятать navigation bar или переопределить кнопку back без возврата `interactivePopGestureRecognizer`
- **SwiftUI: identity view** — `if/else` создаёт разные view и сбрасывает их `@State`, а `.id()` пересоздаёт view целиком. Аналог ключей в Compose
- **SwiftUI: `@State` для reference-объектов** — для `@Observable` класса нужен `@State`, для старого `ObservableObject` — `@StateObject` (а не `@ObservedObject`, иначе объект пересоздаётся)
- **Модальные экраны с iOS 13 по умолчанию — карточка (pageSheet)**, которую можно смахнуть вниз. Если это ломает логику — `isModalInPresentation` или `.fullScreen`

## Платформа

- **Permissions спрашиваются один раз.** Если пользователь отказал — повторный системный диалог не покажется, только отправить в Настройки. Поэтому сначала показывают свой экран-объяснение
- **Нет usage description в `Info.plist` → краш** при запросе разрешения
- **Keychain переживает удаление приложения.** Токен из прошлой установки может "воскреснуть" — обычно чистят Keychain при первом запуске (флаг в UserDefaults)
- **Нет "убитого процесса с восстановлением стека"**: после убийства в фоне — просто холодный старт. Тестировать: запустить, свернуть, убить через Xcode stop
- **Push на симуляторе** работают только как локальная симуляция (drag & drop `.apns` файла или `xcrun simctl push`), для реальных пушей нужен девайс
- **Симулятор ≠ девайс**: нет камеры, другой performance, Keychain и некоторые фреймворки ведут себя иначе. Перед сдачей задачи — проверить на железе
- **App Store review**: приватные API, неописанные permissions, неработающие ссылки, обязательный "Sign in with Apple" при сторонних логинах, удаление аккаунта внутри приложения — частые причины отказа

## Инструменты

- **"Ничего не менял, а не собирается"** — Clean Build Folder (`Cmd+Shift+K`), потом удалить DerivedData (`~/Library/Developer/Xcode/DerivedData`). Помогает удивительно часто
- **Конфликты в `project.pbxproj`** при мёрже — разбирать аккуратно руками, либо проект генерится Tuist/XcodeGen и файл в гите не хранится
- **CocoaPods → открывать `.xcworkspace`**, а не `.xcodeproj`
- **Подпись**: "No profiles for ... were found", "Failed to register bundle identifier" — почти всегда вопрос к команде/админу аккаунта, а не к коду
- **Xcode Previews** часто ломаются в больших проектах — не тратить на это полдня, запускать на симуляторе
- **Crash без stack trace** в Crashlytics — не загружены dSYM
